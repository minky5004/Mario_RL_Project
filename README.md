# 🍄 Mario RL — 강화학습 슈퍼마리오 AI

> **Java(강화학습 두뇌) ↔ Python(게임 환경)** 을 TCP 소켓으로 연결해, 슈퍼마리오 **1-1**을 스스로 학습하는 개인 공부용 프로젝트.
> 표 Q-Learning의 🏁 첫 깃발(DAY7)에서 시작해, **열두 개의 두뇌**를 같은 환경·같은 자(5시드 분포)로 비교·강화하는 **20일의 여정을 완주**했다.

## 🎛 상태 · 행동 · 보상 설계

**상태 — 두 테이블 합산 (tile coding, DAY7의 발견).** 가치는 `Q(s,a) = Q_공통[c][a] + Q_위치[l][a]`, TD 오차는 양쪽에 α/2씩.

| 테이블 | 크기 | 구성 | 역할 |
|---|---|---|---|
| **Q_공통** (위치 무시) | 108 | 벽거리(3) × 구덩이거리(3) × 적거리(4) × 수직방향(3) | **일반화** — "굼바는 어디서든 넘는 것" |
| **Q_위치** (위치 포함) | 1,080 | xZone(30) × [구덩이×적×수직](36) | **안정화** — 특정 지점의 예외를 덧칠 |

위치를 *빼면* 일반화되나 진동하고(DAY7 트라이1), *넣으면* 위치별 암기(DAY6) — **합치면 둘 다**(clear 3→17). 각 신호는 전부 RAM에서: 적 = 적 슬롯 좌표(DAY2), 구덩이 = 바닥 타일맵의 빈 지면(DAY4), 벽 = 지면 위로 솟은 블록(DAY8), 수직방향 = Δy(DAY5).

**행동 7종** (비교 실험은 6개 = 긴 점프 OFF): `NOOP · RIGHT · RIGHT_JUMP · JUMP · LEFT · RIGHT_RUN_JUMP · RIGHT_LONG_JUMP`

**보상** (Python `compute_reward`):

| 사건 | 보상 | 비고 |
|---|---|---|
| 전진 | +0.1 × px | 매 스텝의 밀도 있는 신호 |
| 후퇴 | −5 | |
| 사망 | −100 | `dead_enemy` / `dead_pit`(낙사) 구분 측정 |
| 시간초과 | −50 | ⚠️ 사망보다 덜 아픔 — 진화 계보가 "버티는 겁쟁이"를 선택한 원인(DAY13) |
| 클리어 🏁 | +1000 | x=3161 깃발. **sparse-reward의 근원** — 이 프로젝트 모든 결론의 배경 |

## 🤖 구현된 알고리즘

두뇌는 `Brain` 인터페이스 하나로 추상화돼 있어, **소켓·게임·보상은 그대로 두고 두뇌만 갈아끼워**(`-Dmario.algo`) 같은 1-1·같은 상태 인코딩·**5시드 분포**로 비교했다. *(최종 순위순 — 상세 수치는 [비교 보드](docs/실험일지/%5B비교%5D%20알고리즘%20비교%20보드.md))*

| 알고리즘 | 작동 방식 | 실측 결과 |
|---|---|---|
| **SARSA(λ)** 🥇 | SARSA + **적격흔적** — 최근 밟은 상태들에 "책임 꼬리표"를 남겨 한 번의 오차를 과거로 한꺼번에 전파 | **비교군 최상위.** clear 12배·첫 깃발 3.8배 일찍(5/5)·timeout 최저(17). sparse-reward의 진짜 병목(신용 전파)을 정면으로 품 |
| **Watkins Q(λ)** 🥈 | Q-Learning + **적격흔적** — 단 off-policy라 탐험한 순간 흔적을 **자른다**(Watkins cut) | QL을 분포째 압도(clear 36→225·5/5 깃발) = **QL 계보 첫 강화 성공.** SARSA(λ)와 본선이 겹치는 최상위권 — cut의 비용은 ε 높은 초반에만(첫 깃발 470 vs 230) |
| **n-step SARSA** 🥉 | 실제 보상을 **n칸(8)** 쌓은 뒤 부트스트랩 (n=1이면 SARSA, n=∞면 Monte Carlo) | **MC와 TD를 잇는 다리.** MC에 부트스트랩을 되돌리자 timeout 580→59·clear 5→206으로 부활 |
| **Expected SARSA** | 다음 행동들의 *기대값*(`(1-ε)·max + ε·mean`)으로 갱신 | 분산을 줄여 안정적 — SARSA의 timeout 성향을 QL 쪽으로 완화. plain TD의 마지막 보드 대표 |
| **Q-Learning** | 다음 상태에서 *가장 좋은* 행동을 가정(`max`)해 갱신 | **off-policy** 기준 학습기 — 1막의 주인공(첫 깃발). 보드 자리는 Q(λ)에게 물려줌 |
| **SARSA** | 다음 상태에서 *실제로 고른* 행동의 Q값으로 갱신 | **on-policy** — 보수성이 "낙사 회피"가 아니라 timeout(97)으로 발현. 보드 자리는 SARSA(λ)에게 물려줌 |
| **Double Q-Learning** | 테이블 2벌로 "고르기"와 "값 읽기"를 분리해 최대화 편향 제거 | **이 환경에선 오히려 후퇴**(clear 36→1) — sparse-reward에선 QL의 낙관이 되레 드문 깃발 경로로 미는 힘이었다 |
| **Monte Carlo** | *에피소드가 끝난 뒤* 실제 return으로 갱신(부트스트랩 없음) | 본선에서 TD에 *처음으로 밀림* — timeout이 Random급(끝을 못 냄). 깃발엔 닿음(4/5) |
| **GA v2** ✨ | GA 진단서 셋을 고침 — **softmax 확률 정책** · **공통 테이블만 진화**(8,316→756) · **적합도 = 도달 거리** | **"진화도 고치면 된다"** — 바닥선을 분포째 넘고 깃발까지(best 3161, 2/5)·timeout 1122→292. 단 진화의 천장은 **신용 할당의 부재** |
| **랜덤** | 학습 없이 무작위 행동 | **바닥 기준선**(깃발 0·거리 654) — "학습기라면 적어도 이것보단" |
| **GA (유전 알고리즘)** | 정책 *모집단* → 적합도(보상 합) → 선택·교배·돌연변이 | *바닥선보다도 못한* 첫 학습기(깃발 0·timeout 2배) — 큰 파라미터·빈약 예산·"버티기" 우대 적합도의 합작 |
| **ES (진화 전략)** | 한 부모 + 노이즈 자식들(OpenAI-ES) → 적합도 가중 평균으로 한 걸음 | **전 지표 최하위·유일하게 시간이 갈수록 퇴보** — 단일 부모가 "안전 timeout" 분지로 collapse |

> **on-policy / off-policy** = "내가 실제로 한 행동대로 배우나(보수적)" vs "최선을 가정하고 배우나(공격적)".
> **부트스트랩** = 다음 상태의 *추정값*으로 현재를 갱신(TD) ↔ 끝까지 가본 *실제 결과*로 갱신(Monte Carlo).

### 🔰 예시로 보는 차이 — "구덩이 옆 좁은 길"

마리오가 **오른쪽에 구덩이가 있는 좁은 길**을 지나야 한다고 하자. 빠른 길은 구덩이 *바로 옆*, 안전한 길은 *한 칸 떨어져 도는* 길. 학습 중엔 ε(탐험) 때문에 가끔 무작위로 움직여 실수로 구덩이 쪽으로 뛰기도 한다. 같은 상황에서 알고리즘이 이렇게 갈린다:

**🎯 값 기반 TD — Q-Learning · SARSA · Expected SARSA** *(셋은 "다음 칸의 가치를 무엇으로 보나"만 다르다)*

- **Q-Learning (공격적)** — *"내가 완벽하게만 두면 구덩이 옆 최단길이 최고"* 라고 가정하고 가장자리 길을 배운다. 하지만 학습 중 탐험으로 가끔 발을 헛디뎌 추락 → 점수가 크게 출렁인다. 잘 풀리면 제일 빠르다.
- **SARSA (보수적)** — *"나는 가끔 무작위로도 움직이잖아, 가장자리에선 그러다 죽어"* — 그 위험을 학습에 반영해 구덩이에서 *한 칸 떨어진 길*을 고른다. 조금 돌아가지만 추락이 적어 안정적이다.
- **Expected SARSA (안정)** — SARSA와 같은 신중함인데, 다음 행동을 *운 한 번*에 맡기지 않고 *가능한 다음 행동들의 평균*으로 평가한다. 한 번의 우연에 덜 흔들려 학습이 더 매끄럽다.

**📋 Monte Carlo — 끝나고 복기**

매 칸마다 배우지 않고, *한 판이 끝날 때까지*(구덩이에 빠지거나 깃발 도달) 기다렸다가 "이번 판 결과가 좋았나"로 되짚어 배운다. 시험을 다 치고 채점하는 식 — 실제 결과라 정확하지만(편향 없음), 한 판이 끝나야 알 수 있어 느리고 운에 따라 들쭉날쭉하다(분산 큼).

**🎲 랜덤 · 고정행동 — 바닥선**

아예 배우지 않는다. 동전 던지듯 아무 행동, 또는 무조건 "오른쪽+점프"만 한다. *"학습한 알고리즘이라면 적어도 이것보단 나아야 한다"* 를 재는 기준점이다.

**🧬 GA · ES (진화) — 무리에서 살아남기**

한 마리가 점점 배우는 게 아니라, **마리오 여러 마리(모집단)** 를 동시에 풀어 각자 한 판씩 시키고 *가장 멀리 간 개체만 남긴다*. 그 우수 개체를 *조금씩 바꿔(돌연변이)* 다음 세대를 만들어 반복 → 세대가 갈수록 잘하는 마리오가 나온다. Q값·미분 없이 "되는 놈을 베껴 조금 바꾼다"로만 진화한다. (처음 떠올렸던 *"여럿 풀고 1등만 남기기"* 가 바로 이것 + 돌연변이.)

> 💡 **"가장 멀리 간 개체만 남긴다"가 말처럼 쉽지 않다.** 첫 GA는 *멀리 간* 개체가 아니라 **"안 죽고 버틴"** 개체를 남기고 있었다 — 적합도를 보상 합으로 쟀는데, 시간 초과(−50)가 죽음(−100)보다 덜 아파서 **제자리에서 뭉개는 겁쟁이**가 살아남았던 것. 적합도를 **도달 거리**로 바꾸고(=진짜로 멀리 간 놈만 남김), 정책을 확률적으로 만들어(막히면 다른 행동이 나오게) 고친 게 **GA v2**다. *무엇을 "잘함"으로 정의하느냐가 진화의 전부다.*

## 📏 어떻게 쟀나 (측정 방법론)

이 프로젝트에서 알고리즘만큼 공들인 것이 **측정**이다 — 초반의 실수들이 방법론을 만들었다.

- **추측 말고 측정.** 픽셀 휴리스틱은 굼바 대신 마리오를 잡았고(DAY2), 죽는 위치만 보고 사인을 단정했다가 틀렸다(DAY1). 게임 상태는 RAM에서 읽고, 새 신호는 진단 로그로 검증 후 투입하고, 새 두뇌는 **경계 검증**(예: n=1≡SARSA·λ=0≡QL, Q테이블 오차 0)부터.
- **단일 실행으론 결론 금지.** 같은 코드가 clear 1↔24로 요동쳤다(DAY8). 결론은 **시드 1~5 분포**(mean ± std [min~max])로만, "이겼다"는 **min > max**(분포 비겹침)일 때만. 겹치면 정직하게 "판정 불가".
- **지표도 실험 대상.** 최종 clear는 노이즈가 커서(시드당 0~2회 사건), TD 강화 판정엔 **첫-클리어 판수 · 학습곡선 AUC · 초반 300판 평균**이라는 "얼마나 빨리 배우나" 자를 새로 들었다(DAY15~).
- **로그는 영구 보관, 그래프는 로그에서.** 5시드 원본 로그를 전부 보관(`mario_training_logs/`, 레포 밖) — 재학습 없이 그래프를 재생성하고, 보드의 모든 숫자가 결정적으로 재현된다. maxX는 Java·Python 이중 기록을 **교차검증**(전 기간 불일치 0판).

## 🚀 빠른 시작

**요구사항** — Docker · JDK 17 (Gradle Wrapper 포함).
게임 서버(Python)는 구버전 스택이라 **Docker**로, 두뇌(Java)는 호스트에서 돌린다.

```bash
# 터미널 1 — 게임 서버
docker build -t mario-env .
docker run --rm -p 9999:9999 -p 8081:8081 mario-env   # 8081 = 브라우저 화면 스트림

# 터미널 2 — 학습 두뇌
./gradlew run        # 학습 실행   (build = 컴파일, test = JUnit)
```

화면은 브라우저에서 `http://localhost:8081`.

| `-Dmario.lambda=0.9` | SARSA(λ)·Watkins Q(λ)의 적격흔적 감쇠 λ | 0.9 |
| `-Dmario.nstep=8` | n-step SARSA의 n(실제 보상을 몇 칸 쌓고 부트스트랩할지) | 8 |
| `-Dmario.ga.pop=N -Dmario.ga.evals=K -Dmario.ga.agg=mean\|max -Dmario.ga.hof=true` | GA v2 모집단·평가 판수·적합도 집계·명예의 전당(역대 최고 개체 재주입) | 30·1·mean·false |
| `-Dmario.seed=N` | 난수 시드 고정(재현·시드 비교) | 없음 |
| `-Dmario.port=N` | 서버 포트(병렬 실행용) | 9999 |
| `-Dmario.actions=6` | 쓰는 행동 수(6 = 긴 점프 끔) | 7 |
| `-Dmario.load/save=경로` | Q-Table 이어학습·저장 | 없음 |

```bash
./gradlew run -Dmario.algo=sarsa_lambda -Dmario.seed=1   # SARSA(λ), 시드 1 (비교군 최상위)
./gradlew run -Dmario.algo=q_lambda -Dmario.seed=1       # Watkins Q(λ) (흔적 듀오의 나머지 반쪽)
```

### 5시드 병렬 (비교 실험 재현)

시드마다 게임 서버 + 두뇌를 한 쌍씩, 포트로 격리해 동시에 돌린다(시드 i → 포트 999i). 보드의 모든 비교가 이 방식(6행동·1500판·시드 1~5).

```bash
# 시드 1 예시 — 시드 2~5는 포트만 9992~9995로
docker run --rm -e MARIO_SEED=1 -p 9991:9999 -p 8081:8081 mario-env
./gradlew installDist   # gradle 데몬 락 회피용 배포본 (병렬은 java 직접 실행이 편하다)
java -Dmario.algo=q_lambda -Dmario.seed=1 -Dmario.port=9991 -Dmario.actions=6 \
     -cp "build/install/Mario_RL_Project/lib/*" com.mario.rl.Main
```
