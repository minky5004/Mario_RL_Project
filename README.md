# 🍄 Mario RL — 강화학습 슈퍼마리오 AI

> **Java(강화학습 두뇌) ↔ Python(게임 환경)** 을 TCP 소켓으로 연결해, 슈퍼마리오 **1-1**을 스스로 학습하는 개인 공부용 프로젝트.
> 표 Q-Learning으로 🏁 첫 깃발 클리어까지 도달했고, 지금은 여러 알고리즘을 같은 환경에서 비교하는 중.

<br>

## 🧠 두뇌(Java) ↔ 🎮 게임(Python)

역할을 둘로 쪼개 **소켓으로 연결**했다.

- **Java = AI 두뇌.** 상태를 받아 행동을 정하고, 경험으로 학습한다(Q-Learning · SARSA …). **소켓 클라이언트.**
- **Python = 게임 환경.** `gym-super-mario-bros`(1-1 고정)로 게임을 굴리고 상태·보상을 준다. **소켓 서버(포트 9999).**
- **왜 나눴나** — 강화학습 *로직*은 Java로 깔끔하게 짜고, 게임은 구버전 파이썬 스택이 필요해 Docker에 가둔다. 둘은 **언어·실행환경이 달라도** 소켓 너머로만 대화한다.
- **통신** — 줄바꿈(`\n`) 구분 UTF-8 JSON, 단일 스레드 동기. **한 왕복 = 강화학습 한 스텝**(상태→행동→보상→학습).

<br>

## 🤖 구현된 알고리즘

두뇌는 `Brain` 인터페이스 하나로 추상화돼 있어, **소켓·게임·보상은 그대로 두고 두뇌만 갈아끼워**(`-Dmario.algo`) 같은 1-1·같은 상태 인코딩·**5시드 분포**로 비교한다.

| 알고리즘 | 작동 방식 | 특징 | 상태 |
|---|---|---|:---:|
| **Q-Learning** | 매 스텝, 다음 상태에서 *가장 좋은* 행동을 가정(`max`)해 Q값을 갱신 | **off-policy** — 탐험과 무관하게 최적 정책을 학습, 공격적 | ✅ |
| **SARSA** | 다음 상태에서 *실제로 고른* 행동의 Q값으로 갱신 | **on-policy** — 탐험의 위험을 학습에 반영해 더 보수적·안전 | ✅ |
| **Expected SARSA** | 다음 행동들의 *기대값*(정책 확률로 가중 평균 `(1-ε)·max + ε·mean`)으로 갱신 | 분산을 줄여 더 안정적 — 실측: SARSA의 timeout 성향을 Q-Learning 쪽으로 완화 | ✅ |
| **Monte Carlo** | 한 *에피소드가 끝난 뒤* 실제 받은 보상 총합으로 갱신(부트스트랩 없음) | 편향은 없지만 분산이 크고 느림 — 에피소드형 문제 전용 | ⏳ 예정 |
| **랜덤** | 학습 없이 무작위 행동 | 다른 알고리즘을 견주는 **바닥 기준선** (깃발 0·거리 절반) | ✅ |
| **GA · ES (진화)** | 정책 *모집단*을 굴려 적합도(멀리·clear) 측정 → 상위 선택 → 돌연변이로 다음 세대 | 그래디언트·Q값이 필요 없는 **블랙박스**, 모집단 자체가 탐험을 촉진 | ⏳ 예정 |

> **on-policy / off-policy** = "내가 실제로 한 행동대로 배우나(보수적)" vs "최선을 가정하고 배우나(공격적)".
> **부트스트랩** = 다음 상태의 *추정값*으로 현재를 갱신(TD) ↔ 끝까지 가본 *실제 결과*로 갱신(Monte Carlo).

### 🔰 예시로 보는 차이 — "구덩이 옆 좁은 길"

마리오가 **오른쪽에 구덩이가 있는 좁은 길**을 지나야 한다고 하자. 빠른 길은 구덩이 *바로 옆*, 안전한 길은 *한 칸 떨어져 도는* 길. 학습 중엔 ε(탐험) 때문에 가끔 무작위로 움직여 실수로 구덩이 쪽으로 뛰기도 한다. 같은 상황에서 알고리즘이 이렇게 갈린다:

**🎯 값 기반 TD — Q-Learning · SARSA · Expected SARSA** *(셋은 "다음 칸의 가치를 무엇으로 보나"만 다르다)*

- **Q-Learning (공격적)** — *"내가 완벽하게만 두면 구덩이 옆 최단길이 최고"* 라고 가정하고 가장자리 길을 배운다. 하지만 학습 중 탐험으로 가끔 발을 헛디뎌 추락 → 점수가 크게 출렁인다. 잘 풀리면 제일 빠르다.
- **SARSA (보수적)** — *"나는 가끔 무작위로도 움직이잖아, 가장자리에선 그러다 죽어"* — 그 위험을 학습에 반영해 구덩이에서 *한 칸 떨어진 길*을 고른다. 조금 돌아가지만 추락이 적어 안정적이다.
- **Expected SARSA (안정)** — SARSA와 같은 신중함인데, 다음 행동을 *운 한 번*에 맡기지 않고 *가능한 다음 행동들의 평균*으로 평가한다. 한 번의 우연에 덜 흔들려 학습이 더 매끄럽다.

**📋 Monte Carlo — 끝나고 복기**

매 칸마다 배우지 않고, *한 판이 끝날 때까지*(구덩이에 빠지거나 깃발 도달) 기다렸다가 "이번 판 결과가 좋았나"로 되짚어 배운다. 시험을 다 치고 채점하는 식 — 실제 결과라 정확하지만(편향 없음), 한 판이 끝나야 알 수 있어 느리고 운에 따라 들쭉날쭉하다(분산 큼).

**🎲 랜덤 · 고정행동 — 바닥선**

아예 배우지 않는다. 동전 던지듯 아무 행동, 또는 무조건 "오른쪽+점프"만 한다. *"학습한 알고리즘이라면 적어도 이것보단 나아야 한다"* 를 재는 기준점이다.

**🧬 GA · ES (진화) — 무리에서 살아남기**

한 마리가 점점 배우는 게 아니라, **마리오 여러 마리(모집단)** 를 동시에 풀어 각자 한 판씩 시키고 *가장 멀리 간 개체만 남긴다*. 그 우수 개체를 *조금씩 바꿔(돌연변이)* 다음 세대를 만들어 반복 → 세대가 갈수록 잘하는 마리오가 나온다. Q값·미분 없이 "되는 놈을 베껴 조금 바꾼다"로만 진화한다. (처음 떠올렸던 *"여럿 풀고 1등만 남기기"* 가 바로 이것 + 돌연변이.)

## 🚀 빠른 시작

**요구사항** — Docker · JDK 17 (Gradle Wrapper 포함).
게임 서버(Python)는 구버전 스택이라 **Docker**로, 두뇌(Java)는 호스트에서 돌린다.

```bash
# 터미널 1 — 게임 서버
docker build -t mario-env .
docker run --rm -p 9999:9999 -p 8081:8081 mario-env   # 8081 = 브라우저 화면 스트림

# 터미널 2 — 학습 두뇌
./gradlew run        # 학습 실행   (build = 컴파일, test = JUnit)
```

화면은 브라우저에서 `http://localhost:8081`.

### 실행 옵션 (`-Dmario.*`)

| 옵션 | 뜻 | 기본 |
|---|---|---|
| `-Dmario.algo=qlearning\|sarsa\|expected_sarsa\|random` | 알고리즘 선택 (random=무학습 기준선) | `qlearning` |
| `-Dmario.seed=N` | 난수 시드 고정(재현·시드 비교) | 없음 |
| `-Dmario.port=N` | 서버 포트(병렬 실행용) | 9999 |
| `-Dmario.actions=6` | 쓰는 행동 수(6 = 긴 점프 끔) | 7 |
| `-Dmario.load/save=경로` | Q-Table 이어학습·저장 | 없음 |

```bash
./gradlew run -Dmario.algo=sarsa -Dmario.seed=1   # SARSA, 시드 1
```

```
│   │   ├── RandomBrain.java     #   무학습 바닥 기준선

├── python/
│   └── mario_env_server.py      # 게임 환경 · 보상 · 소켓 서버 · 화면 스트림

```
