# 01. 강화학습이란?

> 이 장의 목표: 머신러닝 안에서 **강화학습이 어디에 있는지** 이해하고,
> 우리 프로젝트가 왜 **Q-Learning(Q-Table)** 을 골랐는지 설명할 수 있게 되는 것.

---

## 1. 머신러닝의 큰 분류

머신러닝은 **"데이터로부터 무엇을, 어떻게 배우는가"** 에 따라 크게 3가지로 나뉩니다.

### ① 지도학습 (Supervised Learning)
- **정답(label)이 있는 데이터**로 학습. "입력 → 정답" 쌍을 잔뜩 보여주고 규칙을 익힘.
- 비유: 문제집에 **답안지가 붙어 있는** 상태로 공부.
- 종류
  - **분류(Classification)**: 고양이/개 구분, 스팸 메일 판별
  - **회귀(Regression)**: 집값 예측, 내일 기온 예측
- 대표 알고리즘: 선형회귀, 결정트리, SVM, 신경망(CNN 등)

### ② 비지도학습 (Unsupervised Learning)
- **정답이 없는 데이터**에서 스스로 패턴·구조를 찾음.
- 비유: 답안지 없이 비슷한 것끼리 **알아서 묶어보기**.
- 종류
  - **군집화(Clustering)**: 고객을 비슷한 그룹으로 묶기
  - **차원 축소(Dimensionality Reduction)**: 데이터 압축·시각화 (PCA 등)
- 대표 알고리즘: K-means, DBSCAN, PCA, 오토인코더

### ③ 강화학습 (Reinforcement Learning, RL) ← **이 프로젝트**
- **정답이 주어지지 않음.** 대신 환경 속에서 **행동을 해보고, 그 결과로 받는 보상(reward)** 을 통해
  "무엇이 좋은 행동인지"를 스스로 터득.
- 비유: 게임을 직접 **플레이하면서 시행착오로** 잘하게 되는 것.

```
       ┌──────────── 행동(Action) ───────────┐
       │                                     ▼
  ┌─────────┐                          ┌──────────┐
  │ Agent   │                          │  환경     │
  │ (마리오  │                          │ (게임)    │
  │  AI 두뇌)│                          │          │
  └─────────┘                          └──────────┘
       ▲                                     │
       └──── 상태(State) + 보상(Reward) ──────┘
```

> 💡 요즘은 ④ **자기지도학습(Self-supervised)** — 데이터 자체에서 정답을 만들어 학습(GPT 같은 LLM) —
> 도 큰 흐름이지만, 위 3가지가 기본 골격입니다.

## 2. 강화학습의 핵심 용어

| 용어 | 영어 | 마리오에서는 |
|------|------|--------------|
| 에이전트 | Agent | AI 두뇌 (Java 쪽) |
| 환경 | Environment | 마리오 게임 (Python 쪽) |
| 상태 | State (s) | 마리오 위치·적 유무·높이 등 |
| 행동 | Action (a) | NOOP, 오른쪽, 점프 … (6가지) |
| 보상 | Reward (r) | 전진 +, 사망 −100, 클리어 +1000 |
| 정책 | Policy (π) | "이 상태에서 무슨 행동을 할까"의 규칙 |
| 에피소드 | Episode | 시작~죽음(또는 클리어)까지 한 판 |

강화학습의 목표는 한 문장으로 이렇습니다:

> **"에피소드 동안 받는 보상의 총합을 최대로 만드는 정책(π)을 찾아라."**

## 3. Q-Table 이란?

**Q-Table = "상태 × 행동" 점수표**입니다. 그냥 **2차원 표(엑셀 시트)** 하나라고 생각하면 됩니다.

- **행(row)** = 상태(state) — "지금 마리오가 어떤 상황인가"
- **열(column)** = 행동(action) — "어떤 버튼을 누를까"
- **칸(cell) 값 = Q값** — "이 상태에서 이 행동을 하면 **앞으로 받을 보상의 기대치**"

여기서 **Q** 는 **Quality(행동의 품질)** 의 Q. "이 상황에서 이 행동이 얼마나 좋은가?"를 숫자로 적어둔 것.

### 예시로 보기

상태 3가지, 행동 3가지뿐이라고 하면:

| 상태 \ 행동 | 가만히(NOOP) | 오른쪽 | 오른쪽+점프 |
|---|---|---|---|
| 평지 | 0.5 | **8.2** | 6.1 |
| 앞에 적 | -3.0 | -5.0 | **12.4** |
| 앞에 구덩이 | 1.0 | -20.0 | **15.7** |

- "앞에 적" 상태 → 표에서 **오른쪽+점프(12.4)** 가 제일 높음 → AI는 이걸 선택
- 처음엔 표가 전부 **0** 으로 시작 → 플레이하며 보상을 받아 칸 값을 조금씩 채워나감
- 우리 프로젝트는 `double[1000][6]` → **상태 1000가지 × 행동 6가지 = 6000칸짜리 표**

> **학습이란 결국 이 표의 숫자들을 정답에 가깝게 갱신해 나가는 것.** 그게 전부입니다.

### Q값을 갱신하는 공식 (벨만 방정식)

```
Q(s,a) ← Q(s,a) + α·[ r + γ·maxQ(s',a') − Q(s,a) ]
         현재값      학습률  보상  할인율·다음최선   현재값
```

- **α (학습률, 0.1)**: 새 정보를 얼마나 반영할지 (크면 빨리 변함)
- **γ (할인율, 0.99)**: 미래 보상을 얼마나 중요하게 볼지 (1에 가까울수록 멀리 봄)
- **maxQ(s', a')**: 다음 상태에서 가장 좋은 행동의 Q값 (= 미래에 잘할 수 있다는 기대)

### 탐험 vs 활용 (epsilon-greedy)

표를 채우려면 **이것저것 해봐야(탐험)** 하고, 동시에 **아는 한 최선(활용)** 도 해야 합니다.

- 확률 **ε** → **무작위 행동** (탐험, Exploration)
- 확률 **1−ε** → **Q값이 가장 큰 행동** (활용, Exploitation)
- ε는 **1.0에서 시작 → 매 에피소드 0.995배씩 감소 → 최소 0.01**
  - 처음엔 막 탐험하다가, 학습이 쌓이면 점점 아는 대로 플레이

### Q-Table의 한계

표 방식은 상태를 "1000가지"처럼 **딱 떨어지게 쪼개야** 합니다. 그래서 마리오 화면(픽셀)을
그대로 못 쓰고, `StateEncoder` 로 "X좌표 구간 + 적 유무 + 높이"처럼 **압축**해서 번호를 매깁니다.
상태가 너무 많아지면(예: 화면 픽셀 전부) 표가 감당이 안 됨 → 이때 표 대신 **신경망**을 쓰는 게 **DQN**.

## 4. 강화학습 알고리즘 지도

강화학습은 크게 **"무엇을 학습하느냐"** 로 갈립니다.

```
강화학습
├── 가치 기반 (Value-based)      "각 행동의 점수(Q)를 배운다"
│    ├── Q-Learning   ← 우리 프로젝트 (표)
│    ├── SARSA
│    └── DQN          (Q를 신경망으로)
│
├── 정책 기반 (Policy-based)     "행동 확률을 직접 배운다"
│    └── REINFORCE
│
└── 액터-크리틱 (Actor-Critic)   "정책 + 가치 둘 다"
     ├── A2C / A3C
     ├── PPO          ← LLM 훈련의 표준
     ├── TRPO
     └── GRPO         ← PPO 개량, DeepSeek가 유명하게 만듦
```

직관적 차이:
- **가치 기반**: "각 행동에 점수를 매기고, 점수 높은 걸 고른다" (Q-Table, DQN)
- **정책 기반**: "점수 계산 없이, 곧장 '이 행동을 할 확률'을 배운다" (PPO, GRPO)

### 알고리즘별 장단점

| 알고리즘 | 분류 | 장점 | 단점 | 어디에 쓰나 |
|---|---|---|---|---|
| **Q-Learning (표)** | 가치 | 가장 단순, 이해·디버깅 쉬움 | 상태 적을 때만 가능, 픽셀 못 씀 | **우리 프로젝트**, 미로/그리드 |
| **SARSA** | 가치 | 더 "안전하게" 학습 | 보수적 | 위험 회피 중요한 환경 |
| **DQN** | 가치 | 신경망으로 **픽셀 입력 가능** | 불안정, 튜닝 까다로움 | 아타리 게임 |
| **REINFORCE** | 정책 | 연속 행동 가능, 단순 | 학습이 들쭉날쭉 | 기초 정책학습 |
| **PPO** | 액터크리틱 | **안정적**, 범용, 사실상 표준 | critic 따로 필요 → 무거움 | 로봇, **ChatGPT RLHF** |
| **GRPO** | 액터크리틱 | **critic 제거 → 가볍고 단순** | 그룹 샘플링 비용, LLM 특화 | **DeepSeek-R1**, LLM 추론 |
| **DDPG/SAC** | 액터크리틱 | **연속 제어**(로봇)에 강함 | 구현 복잡 | 로보틱스, 자율주행 |

## 5. (심화) GRPO 는 무엇인가

**GRPO = Group Relative Policy Optimization (그룹 상대 정책 최적화)**.
DeepSeek가 수학·추론 LLM(DeepSeek-R1)을 훈련하며 유명해진, **PPO를 가볍게 개량한** 알고리즘.

**PPO** 는 행동을 평가하려고 **critic(가치망)이라는 두 번째 신경망**을 둡니다. "이 상태의 가치가
얼마쯤이다"를 예측해서, 실제 보상이 그보다 높으면 좋은 행동이라 판단(이 차이를 **Advantage**라 함).

```
PPO :  Advantage = 실제보상 − critic이_예측한_기대값(V)
       → critic 신경망을 따로 학습 (메모리·계산 2배)

GRPO:  같은 질문에 답을 G개 생성 (예: 8개)
       각 답의 보상: [3, 7, 1, 5, ...]
       Advantage = (내 보상 − 그룹 평균) / 그룹 표준편차
       → "평균보다 잘했으면 +, 못했으면 −"  (critic 불필요!)
```

비유: PPO는 **채점 기준표(critic)** 를 따로 만들어 평가, GRPO는 **같은 시험 본 친구들끼리 상대평가**.

**GRPO 장점**: ① critic 없음 → 메모리·계산 절감 ② 단순함 ③ 검증 가능한 보상(수학 정답·코드
통과)과 궁합 좋음 ④ 그룹 상대비교라 보상 스케일에 덜 민감.
**단점**: 한 문제당 답을 여러 개 생성해야 함(생성 비용), 주로 **LLM 텍스트 생성**에 특화.

---

## 6. 그래서 우리 프로젝트는 무엇을 골랐나

|  | 마리오 (우리) | LLM (GRPO 영역) |
|---|---|---|
| 상태 | 게임 화면/좌표 | 지금까지의 텍스트 |
| 행동 | 6개 버튼(이산) | 다음 단어(수만 개) |
| 보상 | 즉시(매 스텝) | 끝나고 한 번(답이 맞나) |
| 적합 알고리즘 | **Q-Learning / DQN** | **PPO / GRPO** |

→ 마리오처럼 **행동이 몇 개 안 되고 즉시 보상**이 나오는 경우엔 **Q-Learning(표)** 이 가장 적합하고
배우기 좋습니다. 그래서 이 프로젝트는 **테이블 기반 Q-Learning** 을 채택했습니다.

### 채택 정리

| 분류 축 | 우리의 선택 | 의미 |
|---------|------------|------|
| 가치 vs 정책 | **가치 기반** | 각 행동의 Q값을 학습 |
| 모델 기반 vs 프리 | **모델 프리** | 게임 규칙 몰라도, 겪으며 학습 |
| On vs Off-policy | **Off-policy** | 탐험하면서도 최적 기준으로 학습 |
| 표 vs 신경망 | **표(Q-Table)** | DQN 대신 2차원 배열 |

역할 분담:
- **Python** = 게임 환경(실제 마리오 실행) — 상태·보상 제공
- **Java** = AI 두뇌(Q-Learning) — 상태 받아 행동 결정, Q-Table 학습
