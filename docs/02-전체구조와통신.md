## 1. 왜 Java와 Python을 나눴을까?

이 프로젝트는 역할이 둘로 나뉘어 있습니다.

| | Java | Python |
|---|---|---|
| 역할 | **AI 두뇌** (의사결정·학습) | **게임 환경** (마리오 실행) |
| 하는 일 | Q-Learning, 행동 선택, Q-Table 갱신 | 게임 진행, 상태·보상 계산, 화면 출력 |
| 핵심 라이브러리 | (직접 구현) + Gson | `gym-super-mario-bros` |

**왜 굳이 나눴나?**
- 실제 마리오 게임(`gym-super-mario-bros`)은 **Python 생태계**에만 잘 갖춰져 있습니다.
- 반면 우리는 **Java로 강화학습을 직접 구현**하며 공부하는 게 목적입니다.
- 그래서 "게임은 Python에게, 두뇌는 Java에게" 맡기고, 둘을 **소켓**으로 연결합니다.

> 💡 이렇게 서로 다른 언어/프로그램을 잇는 가장 단순하고 보편적인 방법이 **소켓 통신**입니다.

---

## 2. 소켓이란? (아주 짧게)

**소켓(socket)** 은 두 프로그램이 네트워크를 통해 **데이터를 주고받는 통로**입니다.
전화에 비유하면:

- **서버(Server)**: 전화를 **받는 쪽**. 먼저 켜두고 "전화 오길 기다림". → **Python**
- **클라이언트(Client)**: 전화를 **거는 쪽**. → **Java**
- **포트(Port)**: 전화번호 같은 것. 이 프로젝트는 **9999번**.

```
   Python (서버)                       Java (클라이언트)
   "9999번에서 기다릴게"   ◀── 연결 ──   "9999번으로 전화할게"
```

그래서 **반드시 Python 서버를 먼저 켜야** 합니다. Java가 먼저 켜지면 받을 사람이 없겠죠.
(이 문제 때문에 Java에는 "연결 안 되면 3초마다 최대 10번 재시도" 로직이 들어갑니다.)

## 3. 무엇을 주고받나? (JSON)

주고받는 데이터는 **JSON** 형식의 글자입니다. 서로 약속한 두 종류만 오갑니다.

### ① Python → Java : 게임 상태(GameState)

```json
{
  "mario_x": 320,
  "mario_y": 180,
  "enemy_near": false,
  "score": 100,
  "time_left": 380,
  "reward": 3.2,
  "done": false,
  "info": "running"
}
```

| 필드 | 뜻 |
|------|----|
| `mario_x`, `mario_y` | 마리오 좌표 |
| `enemy_near` | 근처에 적이 있는지 |
| `score`, `time_left` | 점수, 남은 시간 |
| `reward` | 이번 행동으로 받은 보상 |
| `done` | 죽었거나 클리어해서 한 판이 끝났는지 |
| `info` | 종료 원인 (`running`/`dead`/`clear`/`timeout`) |

### ② Java → Python : 행동(Action)

```json
{ "action": 2 }
```

숫자 `2`는 [01장](01-강화학습이란.md)에서 본 행동 번호입니다 (2 = 오른쪽+점프).

> 📌 약속: **메시지 하나가 끝나면 줄바꿈(`\n`) 을 붙입니다.** 받는 쪽은 "줄 단위"로 읽어서
> 어디까지가 한 메시지인지 압니다. 인코딩은 **UTF-8**.

## 4. 대화 순서 (가장 중요!)

소켓 통신에서 제일 조심할 것은 **순서**입니다. 둘 다 "상대가 먼저 말하겠지" 하고 기다리면
영원히 멈춥니다(이걸 **데드락/교착**이라고 함). 그래서 순서를 **엄격히** 정합니다.

```
   Python(게임)                         Java(두뇌)
        │                                   │
   reset()으로 한 판 시작                     │
        │                                   │
        │ ── ① 상태(GameState) 전송 ──▶       │
        │                                   │  ② 상태를 숫자로 인코딩
        │                                   │  ③ Q-Table 보고 행동 선택
        │ ◀── ④ 행동(Action) 전송 ──         │
   ⑤ env.step(행동) 실행                      │
   ⑥ 보상·다음상태 계산                        │
        │ ── ⑦ 다음 상태 전송 ──▶             │
        │                                   │  ⑧ Q-Table 갱신(학습)
        │                                   │
        └──────── done 될 때까지 반복 ─────────┘
```

핵심 규칙: **Python 전송 → Java 수신 → Java 전송 → Python 수신** 의 한 방향 흐름을 절대 어기지 않음.
(누가 언제 말하고 들을지 딱 정해져 있어서 교착이 안 생깁니다.)

---

## 5. 이 흐름이 곧 강화학습의 한 바퀴

위 ①~⑧이 바로 [01장](01-강화학습이란.md)에서 배운 강화학습 루프와 똑같습니다.

| 소켓 단계 | 강화학습 용어 |
|-----------|---------------|
| ① 상태 전송 | **상태 s** 관측 |
| ③ 행동 선택 | **행동 a** 선택 (epsilon-greedy) |
| ⑤ step 실행 | 환경이 한 칸 진행 |
| ⑥ 보상 계산 | **보상 r** 획득 |
| ⑦ 다음 상태 | **다음 상태 s'** |
| ⑧ Q-Table 갱신 | **학습** (벨만 방정식) |

즉, **소켓 한 번 왕복 = 강화학습 한 스텝**입니다.

## 6. 코드 구조 미리보기

Java 쪽은 이렇게 나뉩니다 (각 파일은 뒤 장에서 한 줄씩 읽습니다).

```
src/main/java/com/mario/rl/
├── Main.java                ← 시작점, 학습 루프 가동
├── agent/
│   ├── RLAgent.java         ← 에피소드 루프 총괄
│   └── QLearning.java       ← Q-Table 알고리즘 (핵심)
├── network/
│   └── SocketClient.java    ← Python과 소켓 통신
├── model/
│   ├── GameState.java       ← 받는 상태 데이터
│   └── Action.java          ← 행동 6가지
└── util/
    ├── StateEncoder.java    ← 상태 → Q-Table 번호 변환
    └── Logger.java          ← 학습 진행 출력
```

각 클래스가 위 ①~⑧ 중 어디를 담당하는지 연결해 보면:

- **SocketClient** = ①④⑦ 통신 담당
- **StateEncoder** = ② 상태를 번호로
- **QLearning** = ③⑧ 행동 선택 + 학습
- **RLAgent** = 전체 루프를 엮는 지휘자
- **Logger** = 진행 상황 출력
