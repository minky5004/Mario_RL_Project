> 이 장의 목표: **연속적인 게임 상태**(좌표·적 유무 등)를 어떻게 **Q-Table의 번호 한 개**로
> 바꾸는지 이해한다. Q-Learning에서 가장 헷갈리는 부분을 그림으로 푼다.

## 1. 왜 "인코딩"이 필요할까?

[01장](01-강화학습이란.md)에서 Q-Table은 **표**이고, 행(row)은 "상태 번호"라고 했습니다.
그런데 마리오의 실제 상태는 이렇게 **연속적이고 가짓수가 많습니다**:

- `mario_x`: 0 ~ 3000 (정수만 해도 3001가지)
- `mario_y`: 수백 가지
- `enemy_near`: 2가지
- … 이걸 다 곱하면 수십만 ~ 수백만 가지

표로 만들기엔 너무 많습니다. 그래서 **비슷한 상태들을 묶어서 번호 하나로 압축**해야 합니다.
이 압축 작업이 **상태 인코딩(state encoding)** 입니다.

```
연속 상태(수백만 가지)  ──[StateEncoder]──▶  0 ~ 999 번호 (1000가지)
```

> 💡 이렇게 잘게 나눠 묶는 걸 **이산화(discretization)** 라고 합니다.
> "픽셀 단위로 정확히"가 아니라 "이 근방에 있다" 정도로 뭉뚱그리는 것.

---

## 2. 무엇을 기준으로 묶나? (3가지 특징)

파일: `src/main/java/com/mario/rl/util/StateEncoder.java`

이 프로젝트는 상태를 **3가지 특징**으로만 요약합니다.

| 특징 | 처리 | 가짓수 |
|------|------|--------|
| `mario_x` (위치) | 100픽셀씩 끊어 **30구간**으로 | 30 |
| `enemy_near` (적) | 있음(1)/없음(0) | 2 |
| `mario_y` (높이) | y<160 높음(0) / 아니면 낮음(1) | 2 |

"마리오가 **대략 어디쯤** 있고, **적이 가까운지**, **점프 중인지**" 정도만 본다는 뜻입니다.
사람도 마리오를 할 때 딱 이 정도만 보고 판단하죠.

## 3. 코드 읽기

```java
public int encode(GameState state) {
    int xZone = Math.min(state.getMarioX(), X_MAX) / X_ZONE_WIDTH;  // ①
    int enemy = state.isEnemyNear() ? 1 : 0;                        // ②
    int yZone = state.getMarioY() < Y_THRESHOLD ? 0 : 1;            // ③

    int index = (xZone * X_ZONE_WEIGHT) + (enemy * ENEMY_WEIGHT) + yZone; // ④
    return Math.min(index, STATE_SIZE - 1);                          // ⑤
}
```

### ① X좌표 → 구간 번호
```java
Math.min(state.getMarioX(), X_MAX) / X_ZONE_WIDTH
//        └ 3000 넘으면 2999로 자름      └ 100으로 나눔
```
- 예: `mario_x = 320` → `320 / 100 = 3` → **3번 구간**
- `Math.min(..., 2999)`로 먼저 **상한을 막아** 구간이 30을 넘지 않게 합니다.

### ② 적 유무 → 0 또는 1
- `true → 1`, `false → 0`. 단순한 이진화.

### ③ 높이 → 0 또는 1
- `mario_y < 160` 이면 **높음(0)**, 아니면 **낮음(1)**.
- 점프해서 위에 있는지/땅에 있는지를 구분 (좌표계상 y가 작을수록 위쪽).

### ④ 세 숫자를 하나로 합치기 (자리수 트릭)
```java
index = (xZone * 20) + (enemy * 2) + yZone;
```
이건 **여러 자릿수를 한 숫자로 합치는** 방식입니다. 10진수에서 `3,4,5`를 `345`로 합칠 때
`3*100 + 4*10 + 5` 하는 것과 같은 원리예요.

```
 xZone(0~29) ── ×20 ──┐
 enemy(0~1)  ── ×2  ──┤──(더하기)──▶ 고유한 index 하나
 yZone(0~1)  ───────  ┘
```
이렇게 곱셈 가중치를 다르게 주면 **세 특징의 조합마다 서로 겹치지 않는 번호**가 나옵니다.

### ⑤ 안전장치: 1000 넘지 않게
```java
return Math.min(index, STATE_SIZE - 1);  // 최대 999
```
- Q-Table은 `double[1000][6]` 이라 **인덱스가 1000 이상이면 프로그램이 터집니다**
  (ArrayIndexOutOfBounds).
- 그래서 마지막에 `Math.min`으로 **절대 999를 넘지 않도록** 막습니다. (방어적 프로그래밍)

> 🔎 참고: 위 공식의 실제 최댓값은 `29*20 + 1*2 + 1 = 583`이라 1000을 넘지 않습니다.
> 그래도 혹시 모를 변경에 대비해 `Math.min`을 둡니다.

## 4. 매직넘버를 상수로 빼둔 이유

코드에 `20`, `100`, `160` 같은 숫자가 직접 박혀 있으면 나중에 "이 20이 뭐였지?" 하게 됩니다.
그래서 전부 **이름 붙은 상수**로 빼뒀습니다.

```java
private static final int X_ZONE_WIDTH = 100;   // 구간 폭
private static final int Y_THRESHOLD  = 160;   // 높이 기준
public  static final int STATE_SIZE   = 1000;  // Q-Table 행 개수
```

특히 `STATE_SIZE`는 `public` 입니다 — 다음 장의 `QLearning`이 Q-Table 크기를 만들 때
**같은 값을 공유**하기 위해서입니다. ("진실의 출처는 한 곳에" 원칙)
