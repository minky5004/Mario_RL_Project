# 06. 코드 한 줄씩 읽기 — 학습 로거(Logger)

> 이 장의 목표: 학습이 **잘 되고 있는지 눈으로 확인**하는 도구를 만든다.
> 강화학습은 오래 돌아가므로, "지금 잘 배우는 중인가?"를 보여주는 로그가 꼭 필요하다.

[← 이전: 05. 상태 인코딩(StateEncoder)](05-코드읽기-상태인코딩.md)

---

## 1. 왜 로거가 필요한가?

강화학습은 수백 에피소드를 **묵묵히 반복**합니다. 출력이 없으면 우리는
"마리오가 늘고 있는지, 멈췄는지" 전혀 알 수 없습니다. 그래서 **두 종류의 로그**를 둡니다.

| 로그 | 언제 | 용도 |
|------|------|------|
| `logEpisode` | 한 판 끝날 때마다 | "이번 판 성적표" (항상 출력) |
| `logStep` | 매 스텝마다 | 아주 자세한 디버깅 (평소엔 끔) |

---

## 2. 에피소드 요약: `logEpisode`

파일: `src/main/java/com/mario/rl/util/Logger.java`

```java
public void logEpisode(int episode, double totalReward, int maxX, double epsilon) {
    System.out.printf(
        "[Episode %4d] Total Reward: %8.1f | Max X: %5d | Epsilon: %.3f%n",
        episode, totalReward, maxX, epsilon);

    if (episode % SEPARATOR_INTERVAL == 0) {
        System.out.println(SEPARATOR);
    }
}
```

출력은 이렇게 보입니다:

```
[Episode   42] Total Reward:  1243.5 | Max X:  1820 | Epsilon: 0.812
```

### 이 4개 숫자를 왜 보여줄까? (학습 관찰 포인트)

| 항목 | 의미 | 학습이 잘 되면 |
|------|------|----------------|
| `Episode` | 몇 번째 판인가 | — |
| `Total Reward` | 이번 판 보상 총합 | **점점 올라감** 📈 |
| `Max X` | 가장 멀리 간 거리 | **점점 오른쪽으로** ▶ |
| `Epsilon` | 탐험 비율 | **점점 0에 가까워짐** (1→0.01) |

> 💡 이 셋의 추세를 보면 학습 상태를 알 수 있습니다.
> `Total Reward`와 `Max X`가 오르고 `Epsilon`이 내려가면 → **잘 배우는 중!**

### `printf`의 포맷 기호 읽기
```
%4d   → 정수를 최소 4칸 폭으로 (오른쪽 정렬)   예: "  42"
%8.1f → 실수를 8칸 폭, 소수점 1자리           예: "  1243.5"
%.3f  → 실수를 소수점 3자리                   예: "0.812"
%n    → 줄바꿈 (OS에 맞는)
```
폭을 맞춰 출력하면 숫자가 **세로로 정렬**돼 추세를 한눈에 보기 좋습니다.

### 10판마다 구분선
```java
if (episode % SEPARATOR_INTERVAL == 0) {   // SEPARATOR_INTERVAL = 10
    System.out.println(SEPARATOR);
}
```
- `episode % 10 == 0` → 10, 20, 30… 번째마다 `------` 선을 그어 **묶음으로 보기 쉽게**.

## 3. 스텝 상세 로그: `logStep` (평소엔 꺼둠)

```java
private boolean verbose = false;   // 기본 꺼짐

public void logStep(int step, Action action, double reward) {
    if (!verbose) return;          // 꺼져 있으면 아무것도 안 함
    System.out.printf("  step %4d | action: %-14s | reward: %7.2f%n",
            step, action, reward);
}
```

- 매 스텝(초당 수십 번)을 다 찍으면 **화면이 폭주**합니다. 그래서 평소엔 `verbose = false`로 꺼둠.
- 버그를 깊게 파야 할 때만 `setVerbose(true)`로 켭니다.

> 이렇게 "필요할 때만 켜는 스위치"를 두는 건 흔한 디버깅 패턴입니다.
> `%-14s`의 `-`는 **왼쪽 정렬**(행동 이름은 길이가 달라서 왼쪽 정렬이 보기 좋음).

---

## 4. 작은 클래스지만 중요한 이유

`Logger`는 로직이 거의 없는 작은 클래스입니다. 하지만 **"학습을 관찰할 수 없으면 개선할 수 없다"**
는 점에서 실험에 꼭 필요합니다. (머신러닝에서 로그·그래프는 절반의 일입니다.)

2. `logStep`을 항상 켜두면 어떤 문제가 생길까? 그래서 왜 `verbose` 스위치를 뒀을까?
3. `%4d`와 `%-14s`에서 숫자 정렬 방향이 다른 이유는?
4. `Max X`는 오르는데 `Total Reward`가 안 오른다면, 보상 설계의 무엇을 의심해볼 수 있을까?
