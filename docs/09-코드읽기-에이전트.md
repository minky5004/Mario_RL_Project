## 1. 지휘자의 부품들 (의존성 주입)

파일: `src/main/java/com/mario/rl/agent/RLAgent.java`

```java
public RLAgent(QLearning qLearning, SocketClient socketClient,
               StateEncoder stateEncoder, Logger logger) {
    this.qLearning = qLearning;
    this.socketClient = socketClient;
    this.stateEncoder = stateEncoder;
    this.logger = logger;
}
```

`RLAgent`는 스스로 부품을 만들지 않고 **밖에서 받아옵니다**(이걸 **의존성 주입**이라 함).

| 부품 | 역할 | 배운 장 |
|------|------|---------|
| `QLearning` | 행동 선택 + 학습 | [07](07-코드읽기-Q러닝.md) |
| `SocketClient` | Python과 통신 | [08](08-코드읽기-소켓통신.md) |
| `StateEncoder` | 상태 → 번호 | [05](05-코드읽기-상태인코딩.md) |
| `Logger` | 진행 출력 | [06](06-코드읽기-로거.md) |

> 💡 이렇게 부품을 밖에서 받으면, 나중에 테스트할 때 가짜 부품으로 바꿔 끼우기 쉽습니다.

## 2. 바깥 루프: `train` — 여러 판 반복

```java
public void train(int maxEpisodes) throws IOException {
    for (int episode = 1; episode <= maxEpisodes; episode++) {
        runEpisode(episode);   // 한 판
    }
}
```

- 그냥 "한 판(`runEpisode`)을 `maxEpisodes`번 반복"이 전부입니다.
- 판을 거듭할수록 Q-Table이 똑똑해지고 epsilon이 줄어듭니다.

---

## 3. 안쪽 루프: `runEpisode` — 한 판의 일생 ⭐

이게 [02장](02-전체구조와통신.md)의 ①~⑧ 흐름 그 자체입니다.

```java
private void runEpisode(int episode) throws IOException {
    GameState current = socketClient.receiveGameState();   // ★ 첫 상태 받기
    int state = stateEncoder.encode(current);

    double totalReward = 0.0;
    int maxX = current.getMarioX();
    int step = 0;

    while (true) {
        int actionIndex = qLearning.selectAction(state);                 // 1) 행동 선택
        socketClient.sendAction(Action.fromValue(actionIndex));          //    전송

        GameState next = socketClient.receiveGameState();                // 2) 결과 받기
        int nextState = stateEncoder.encode(next);
        double reward = next.getReward();
        boolean done  = next.isDone();

        qLearning.update(state, actionIndex, reward, nextState, done);   // 3) 학습

        totalReward += reward;                                           // 4) 통계
        maxX = Math.max(maxX, next.getMarioX());
        logger.logStep(step, Action.fromValue(actionIndex), reward);

        state = nextState;                                               // 5) 다음 준비
        step++;
        if (done) break;
    }

    qLearning.decayEpsilon();                                            // 판 끝: 탐험↓
    logger.logEpisode(episode, totalReward, maxX, qLearning.getEpsilon());// 요약 출력
}
```

### 단계별로 02장과 연결

| 코드 | 02장 흐름 | 07장 메서드 |
|------|-----------|-------------|
| `receiveGameState()` (첫 상태) | ① 상태 전송→수신 | — |
| `encode(current)` | ② 인코딩 | [StateEncoder](05-코드읽기-상태인코딩.md) |
| `selectAction(state)` | ③ 행동 선택 | [selectAction](07-코드읽기-Q러닝.md) |
| `sendAction(...)` | ④ 행동 전송 | — |
| `receiveGameState()` (다음) | ⑤⑥⑦ step·보상·다음상태 | — |
| `update(...)` | ⑧ 학습 | [update](07-코드읽기-Q러닝.md) |

> 📌 **순서가 생명**: `receive → send → receive` 를 정확히 지켜야 [02장](02-전체구조와통신.md)의
> 데드락이 안 납니다. Python도 `send → receive → send` 로 짝을 맞춰 기다립니다.

### `Action.fromValue(actionIndex)` 가 왜 필요?
- `QLearning.selectAction`은 **숫자**(0~5)를 돌려줍니다.
- `SocketClient.sendAction`은 **`Action` enum**을 받습니다.
- 그래서 [04장](04-코드읽기-모델.md)의 `fromValue`로 숫자 → enum 변환을 끼워 넣습니다.

### `while(true)` + `if (done) break`
- 한 판이 **몇 스텝 걸릴지 미리 알 수 없으니**(죽을 때까지/클리어까지) 무한 루프로 돌다가,
- Python이 `done=true`를 보내오면 그때 빠져나옵니다.

## 4. 통계는 왜 모으나?

```java
totalReward += reward;                 // 이번 판 총 보상
maxX = Math.max(maxX, next.getMarioX()); // 가장 멀리 간 지점
```

- 이 둘이 [06장](06-코드읽기-로거.md)의 `logEpisode`로 출력돼 **학습 추세**를 보여줍니다.
- Q-Table 학습에는 안 쓰이고, **순전히 우리가 관찰하기 위한** 값입니다.

---

## 5. 판이 끝나면

```java
qLearning.decayEpsilon();   // 다음 판은 탐험을 조금 덜 하게
logger.logEpisode(...);     // 성적표 출력
```

- `decayEpsilon`은 **에피소드당 한 번만** ([07장](07-코드읽기-Q러닝.md)). 스텝마다 줄이면 너무 빨리 식습니다.
