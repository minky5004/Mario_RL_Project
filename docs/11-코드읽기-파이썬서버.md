## 0. 이 서버가 하는 일

파일: `python/mario_env_server.py`

```
Java(두뇌)  ◀── 상태(GameState JSON) ──  Python 서버  ── 행동 적용 ──▶  마리오 게임
            ── 행동(Action JSON) ──▶
```

- `gym-super-mario-bros` 로 **진짜 마리오 1-1** 을 실행
- 매 스텝 게임 상태를 Java 에 보내고, Java 가 고른 행동을 게임에 적용
- 보상/종료를 계산해 다시 Java 에 전달 (= [02장](02-전체구조와통신.md)의 ⑤⑥⑦)

## 1. 행동 매핑 — Java 의 숫자를 게임 버튼으로

```python
CUSTOM_MOVEMENT = [
    ["NOOP"],              # 0 NOOP
    ["right"],             # 1 RIGHT
    ["right", "A"],        # 2 RIGHT_JUMP   (A = 점프)
    ["A"],                 # 3 JUMP
    ["left"],              # 4 LEFT
    ["right", "B", "A"],   # 5 RIGHT_RUN_JUMP (B = 달리기)
]
env = JoypadSpace(env, CUSTOM_MOVEMENT)
```

- 리스트의 **순서(인덱스)** 가 곧 [04장](04-코드읽기-모델.md) `Action` 의 번호와 1:1 로 맞습니다.
- Java 가 `{"action": 2}` 를 보내면 → `CUSTOM_MOVEMENT[2]` = `right + A` = 오른쪽 점프.

> 📌 이 순서가 어긋나면 마리오가 엉뚱한 행동을 합니다. **Java enum 순서 = 이 리스트 순서**가 계약.

## 2. 통신 — 프로토콜을 Python 쪽에서 지키기

```python
def serve(conn, env):
    rfile = conn.makefile("r", encoding="utf-8")
    wfile = conn.makefile("w", encoding="utf-8")

    def send_state(state):
        wfile.write(json.dumps(state) + "\n")   # ← \n 으로 메시지 구분
        wfile.flush()                            # ← 즉시 보내기 (데드락 방지)

    while True:                                  # 에피소드 무한 반복 (항상 1-1)
        env.reset()
        obs, _, done, info = step_compat(env, 0) # reset 직후 NOOP 한 번 → 초기 info 확보
        prev_x = int(info.get("x_pos", 0))
        send_state(build_state(info, 0.0, False, "running", obs))  # ① 첫 상태 먼저!

        while not done:
            line = rfile.readline()              # ② Java 행동 수신
            action = int(json.loads(line)["action"])
            obs, _, done, info = step_compat(env, action)  # ③ 한 스텝 진행
            reward, status = compute_reward(prev_x, info, done)
            prev_x = int(info.get("x_pos", prev_x))
            send_state(build_state(info, reward, done, status, obs))  # ④ 결과 전송
        # done 보낸 뒤 recv 없이 위로 → reset → 첫 상태 전송
```

### [02장](02-전체구조와통신.md) 계약과의 대응
- **① 첫 상태를 먼저 send** → Java `runEpisode` 가 `receive` 부터 시작하니까 ([09장](09-코드읽기-에이전트.md)).
- **② recv → ③ step → ④ send** 반복 → "Python 전송 → Java 수신 → Java 전송 → Python 수신".
- **done 을 보낸 뒤에는 recv 하지 않음** → Java 는 종료 상태에 행동을 안 보내므로, 여기서 recv 하면 **멈춤**. 그래서 곧장 `reset` 후 다음 첫 상태를 보냄. ⚠️ 가장 헷갈리는 지점.
- `\n` + `flush()` → [08장](08-코드읽기-소켓통신.md)에서 본 그 약속.

### `reset` 직후 NOOP 한 스텝을 하는 이유
`env.reset()` 은 화면(obs)만 주고 `x_pos` 같은 **info 는 안 줄 수 있습니다**. 그래서 NOOP(가만히)
한 스텝을 밟아 **초기 info 를 확보**한 뒤 첫 상태로 보냅니다. (Java 는 첫 상태의 보상을 어차피
안 쓰므로 안전 — [09장](09-코드읽기-에이전트.md) 참고)

## 3. 보상 계산 — docs/03 표를 코드로

```python
def compute_reward(prev_x, info, done):
    dx = int(info.get("x_pos", prev_x)) - prev_x
    reward = dx * 0.1 if dx > 0 else (-5.0 if dx < 0 else 0.0)
    status = "running"
    if info.get("flag_get"):              # 깃발 = 클리어
        reward, status = 1000.0, "clear"
    elif done:
        if int(info.get("time", 1)) <= 0: # 시간 0 = 시간초과
            reward, status = -50.0, "timeout"
        else:                              # 그 외 종료 = 사망
            reward, status = -100.0, "dead"
    return reward, status
```

[03장](03-보상설계.md)의 보상표(전진 `dx×0.1`, 후퇴 −5, 사망 −100, 클리어 +1000, 시간초과 −50)를
**그대로** 옮긴 것입니다. **보상 규칙은 Python 이 계산**하고, Java 는 그 숫자를 받아 학습에만 씁니다
([03장 5절](03-보상설계.md)).

## 4. enemy_near — 화면 픽셀로 적 찾기 (휴리스틱)

```python
def detect_enemy_near(obs):
    region = obs[:, 110:150, :]        # 마리오 앞쪽 영역
    r, g, b = region[...,0], region[...,1], region[...,2]
    mask = (r>140)&(r<220)&(g>50)&(g<130)&(b<100)&(r>g)&(g>b)  # 굼바 갈색
    return bool(mask.sum() > 20)
```

- 마리오는 스크롤 중 화면상 **일정 위치(~110px)** 에 머뭅니다. 그 **오른쪽 영역**에서
  **굼바 갈색 픽셀**이 일정 수 이상이면 "적이 가깝다"고 봅니다.
- ⚠️ 정확한 물체 인식이 아니라 **대략적인 색 기반 추정**(휴리스틱)입니다. 학습엔 이 정도로 충분.
- 이 값이 [05장](05-코드읽기-상태인코딩.md)의 `enemy_near` 로 들어가 상태 번호를 가릅니다.

## 5. 버전·gym API 방어

```python
def step_compat(env, action):
    result = env.step(action)
    if len(result) == 5:               # 신 API: obs, reward, terminated, truncated, info
        obs, reward, terminated, truncated, info = result
        done = terminated or truncated
    else:                              # 구 API: obs, reward, done, info
        obs, reward, done, info = result
    return obs, reward, bool(done), info
```

gym 버전마다 `step` 반환 개수(4개/5개)가 달라서, **둘 다 받아주도록** 감쌌습니다. (구버전 스택의
대표적인 함정을 미리 막는 방어 코드)

## 6. 왜 Docker 인가 + 실행 방법

이 라이브러리들은 **Python 3.8~3.10** 에서만 잘 깔립니다(현재 PC 는 3.13). 그래서 **Python 3.10
컨테이너 안에 격리**해서 돌립니다. 자세한 비교는 [부록](부록-게임환경-구현선택지.md).

```dockerfile
FROM python:3.10-slim
RUN apt-get install -y build-essential      # nes-py(C++) 컴파일용
COPY requirements.txt . && pip install -r requirements.txt
COPY mario_env_server.py .
CMD ["python", "mario_env_server.py"]
```

### 실행 순서
```bash
# 1) 게임 서버 컨테이너 빌드 & 실행 (헤드리스)
docker build -t mario-env ./python
docker run --rm -p 9999:9999 mario-env      # 포트를 호스트로 열어줌

# 2) Windows 에서 Java 두뇌 실행
./gradlew run                                # localhost:9999 로 접속 → 학습 시작
```

- `HOST="0.0.0.0"` + `-p 9999:9999` 덕분에 컨테이너 밖(Windows)의 Java 가 접속됩니다.
- **헤드리스**라 게임 창은 없고, Java 콘솔의 `[Episode ...]` 로그로 학습을 관찰합니다.
  (화면을 보고 싶으면 [부록](부록-게임환경-구현선택지.md)의 noVNC/녹화/WSL 참고)
