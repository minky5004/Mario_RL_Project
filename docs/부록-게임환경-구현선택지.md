## 0. 전제: Java는 안 바꿔도 된다

[02장](02-전체구조와통신.md)에서 Java(두뇌)와 Python(게임)을 **소켓(포트 9999)** 으로 분리해뒀습니다.
덕분에 **게임을 무엇으로 만들든 Java 코드는 그대로**이고, 바꾸는 건 `python/` 서버의
"게임을 돌리는 부분"뿐입니다.

```
Windows ── Java(두뇌, IntelliJ) ──localhost:9999──▶ Python(게임 환경)
                                                    └ 이 부분만 갈아끼움
```

## 1. 왜 고민이 생겼나 (문제)

원래 계획한 라이브러리 묶음이 **2022년쯤 멈춘 구버전**이라, 지금 PC의 **Python 3.12/3.13**에서는
설치가 거의 실패합니다.

| 라이브러리 | 문제 |
|---|---|
| `numpy 1.24.0` | Python 3.12/3.13용 설치 파일(wheel) 없음 → 소스 빌드 실패 |
| `nes-py 8.2.1` | C++ NES 에뮬레이터 직접 컴파일 → Windows에선 Visual C++ 빌드도구 필요, 3.11+에서 깨짐 |
| `gym-super-mario-bros 7.4.0` | 위 둘에 의존, 옛 gym API 가정 |

→ 이 스택은 **Python 3.8 ~ 3.10**을 원합니다. 그래서 "환경을 어떻게 맞출까"가 핵심 결정.

## 2. 선택지 비교

### A. `stable-retro` — 진짜 SMB를 에뮬레이터로
- **정체**: Farama 재단이 유지보수하는 gym-retro 후속작. NES 게임을 에뮬레이터로 돌리고
  `SuperMarioBros-Nes` 통합을 기본 제공.
- **준비**: `pip install stable-retro` (최신 Python에 wheel 제공, 컴파일러 대체로 불필요).
  단 **ROM은 본인 소유분을 직접 등록**(`python -m retro.import`).
- 👍 진짜 마리오 1-1, 최신 파이썬에서 비교적 수월, 렌더링 됨
- 👎 ROM 필요(법적/구하기), `enemy_near`는 따로 구현, retro API 학습 곡선

### B. `pygame` 자작 마리오 — 우리가 직접 만든 게임
- **정체**: 닌텐도 게임 대신 **마리오풍 횡스크롤 게임을 직접 구현**
  (오른쪽 이동, 구덩이, 굼바, 깃발).
- **준비**: `pip install pygame` **하나로 끝** (지금 Python 3.13에서 바로 됨).
- 👍 **즉시 실행**, 설치 지옥 0, 상태·보상 완전 제어(=docs와 100% 일치), 그래픽으로 학습 관찰, 공부엔 최고
- 👎 "진짜 SMB" 아님(자작 클론), 게임 로직 코드(~200~300줄)를 직접 작성

### C. Docker / WSL — 원래 구버전 스택을 격리해서 그대로
- **정체**: 원 스펙 `gym-super-mario-bros`를 버리지 않고, **Python 3.10 리눅스 환경에 격리**해 실행.
- **준비**: Docker Desktop 또는 WSL2 설치. **Java는 Windows에 그대로**, Python만 컨테이너/WSL.
- 👍 진짜 마리오 1-1, 원 스펙 그대로, 재현성 좋음
- 👎 Docker/WSL 세팅 한 번 필요, 옛 gym API 이슈는 남음(`step_compat`로 흡수)

### D. 더미 서버 — 검증용 (참고)
- **정체**: gym 없이 **표준 라이브러리만**으로 "가짜 마리오" 서버 → Java 학습 루프 검증.
- 👍 설치 0, 지금 바로 / 👎 실제 게임 아님(그래픽·물리 없음)

## 3. C를 고른다면: Docker vs WSL2

C 안에서도 두 갈래가 있고, **게임 화면(GUI)** 에서 갈립니다.

| | 게임 창(GUI) | 난이도 | 비고 |
|---|---|---|---|
| **Docker** | ❌ 어려움(X서버 포워딩) → 보통 화면 없이 로그만 | 중 | 헤드리스 학습엔 깔끔 |
| **WSL2 (Win11)** | ✅ **WSLg로 게임 창이 그냥 뜸** | 중 | 화면 보려면 이쪽 |

> **둘 다 Java는 Windows에 그대로 두고 Python만 격리.** 도커로 띄울 땐 컨테이너 안에서
> 서버를 `0.0.0.0`으로 바인딩하고 `-p 9999:9999`로 포트를 열면 Java가 `localhost:9999`로 접속.

### 토폴로지 (C 공통)
```
┌─ Windows 호스트 ─────────────────────────────┐
│   IntelliJ에서 Java 실행 (./gradlew run)       │
│        │  localhost:9999                      │
│        ▼                                      │
│   ┌─ Docker 컨테이너 / WSL2 ──────────────┐    │
│   │  Python 3.10 + gym-super-mario-bros  │    │
│   │  서버가 9999 에서 대기                 │    │
│   └──────────────────────────────────────┘    │
└──────────────────────────────────────────────┘
```

---

## 4. WSL2 란?

**WSL2 = Windows 안에서 진짜 리눅스(Ubuntu 등)를 돌리는 공식 기능** (Windows Subsystem for Linux 2).

- 마이크로소프트가 **진짜 리눅스 커널**을 가벼운 가상머신으로 Windows에 내장.
- 시작 메뉴에서 "Ubuntu"를 켜면 리눅스 터미널 → `apt`, `pip` 등 리눅스 명령 그대로 사용.
- **Win11의 WSLg** 덕분에 **리눅스 GUI 창이 Windows 화면에 그냥 뜸** (예전엔 X서버 별도 필요).
- 리눅스에선 `nes-py` 같은 구버전 라이브러리가 **잘 깔림**(gcc 기본 내장).
- **localhost가 Windows ↔ WSL2 사이에 공유**돼 Java가 `localhost:9999`로 그냥 접속.

설치: 관리자 PowerShell에서 `wsl --install` → 재부팅. 확인: `wsl -l -v` 또는 `wsl --status`.

## 5. 한눈 비교

| | 진짜 마리오? | 지금 3.13에서 바로? | 추가 설치 | 그래픽 | 코딩량 |
|---|---|---|---|---|---|
| **A** stable-retro | ✅ | 대체로 OK | ROM 등록 | ✅ | 중 |
| **B** pygame 자작 | ❌(클론) | ✅ | `pip install pygame` | ✅ | 중(게임 로직) |
| **C** Docker/WSL | ✅ | (격리 환경) | Docker 또는 WSL | △ / ✅(WSL) | 소(설정 위주) |
| **D** 더미 | ❌ | ✅ | 없음 | ❌ | 소 |

**고르는 기준 한 줄**
- "지금 바로, 깔끔하게, 공부 목적" → **B**
- "무조건 진짜 그 게임" → **A**(ROM 있으면) 또는 **C(WSL 권장)**
- "원 스펙 그대로 고수 + 화면도 보고 싶다" → **C(WSL2)**
- "일단 코드가 도는지만 검증" → **D**

## 6. 결정 기록

- ✅ **확정: C — Docker** (원 스펙 `gym-super-mario-bros`를 Python 3.10 컨테이너에 격리)
- 실행 방식: **헤드리스 먼저**(게임 창 없이 로그로 학습 관찰). `enemy_near`는 화면 픽셀(obs)로
  계산되므로 창 없이도 학습은 정상 동작.
- 화면 보기는 **나중에 얹기**(도커 유지): ② noVNC(브라우저로 보기) 또는 ③ 프레임 녹화(mp4).
  (정 안 되면 WSL2로 전환도 가능)
- 진행 순서:
  1. `python/` 에 `mario_env_server.py`(`0.0.0.0` 바인딩, 헤드리스) + `requirements.txt` + `Dockerfile` 작성
  2. `docker build` → `docker run -p 9999:9999` 로 서버 컨테이너 실행
  3. Windows의 Java(`./gradlew run`)가 `localhost:9999` 로 접속해 학습 시작
