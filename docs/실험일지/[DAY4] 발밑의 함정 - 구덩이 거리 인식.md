## 트라이 1 — 구덩이 거리 인식

### 변경
- Python: 바닥 타일맵에서 앞 구덩이(빈 지면)까지 거리를 단계화하는 `detect_pit_distance`(굼바 거리화와 대칭). **상태에 넣기 전 임시 `[pit]` 로그로 검증**(픽셀이 두 번 속인 교훈).
- 검증 후 `GameState.pit_dist` + `StateEncoder` 차원 추가(3단계). 보상·다른 인코딩 그대로.

### 가설
- 1순위 = 감지가 진짜인지. 효과는 제한적일 수 있다 — 구덩이는 위치 고정이라 **xZone이 이미 대리**(DAY2 enemy_dist 논리). 단 구덩이는 회복 불가라 "코앞" 정보가 굼바보다 결정적일 수도.

### 결과 — 신호는 진짜, 효과는 제한적 (가설 적중)

![DAY4 트라이1 학습 그래프](images/day4-try1-graph.png)

**① 감지는 진짜** — pitDist `96→80→…→16` 단조 감소, 구덩이 위 `None`, 낙사 위치와 일치. 교차검증 불일치 0.

**② 수치는 거의 안 바뀜:**

| 지표 | DAY3-T1 | **DAY4-T1** | |
|---|---|---|---|
| 평균 Max X | 764 | 756 | ≈ |
| 낙사 | 125 | 116 | 소폭▼ |
| 첫 굼바 통과율 | 75% | 72% | ≈ |
| best | 1874 | 2742 | ▲(단일 분산) |

- **첫 구덩이 도달 124판 중 통과 52%** — 절반은 *알고도* 빠진다. 후반 greedy에도 추세 없이 진동(DAY2 굼바가 후반에 오르던 것과 대비).

### 결론
- 예측대로 "효과 제한적" — 위치 고정이라 xZone이 이미 대리(DAY2 데자뷰).
- **진짜 병목은 인식이 아니라 점프 제어** — 코앞인 걸 알려줘도 타이밍·거리를 못 맞춘다. 굼바는 점프만 하면 넘지만 구덩이는 시작 위치가 어긋나면 무조건 추락.

## 트라이 2 — 구덩이 통과 보너스 (+50)

### 변경
- 구덩이를 무사히 건너면 **+50**(`PIT_CLEAR_BONUS`). 감지 = 구덩이 절대 x 기억 → 폭 너머(+32px) 생존 시 통과(빠지면 보너스 없음). `pitclears=N` + 임시 `[clear]` 로그 검증.

### 가설
- 트라이1 결론이 "병목=제어"라면 **결과(통과)를 보상해도 효과 제한적**일 것. 어느 쪽이든 결론이 남는다.

### 결과 — 감지는 진짜, 통과율은 오히려 ▼

![DAY4 트라이2 학습 그래프](images/day4-try2-graph.png)

`[clear]` 검증 통과(첫·둘째 구덩이에서만 정확히 발화, "첫은 넘고 둘째에서 빠짐"도 정합).

| 지표 | 트라이1 | **트라이2 (+50)** | |
|---|---|---|---|
| 평균 Max X | 756 | 737 | ≈ |
| 낙사 | 116 | 120 | ≈ |
| 첫 구덩이 통과 | 64판(13%) | **46판(9%)** | ▼ |
| **도달판 중 통과율** | 52% | **35%** | ▼ |

### 결론
- **가설 적중(더 강하게)** — 통과를 보상해도 통과율은 안 오르고 오히려 ▼. **넘으려면 이미 제어가 돼야 하는데 보너스는 그 제어를 못 만든다**(결과를 칭찬해도 수단이 없으면 헛돈다 — DAY3 트라이2와 같은 구조). ▼는 보너스가 "구덩이 돌진"을 부추긴 정황(단일 실행 분산일 수도).
- **인식(트1)도 보상(트2)도 막혔다 → 남은 병목 = 제어(공중 상태 인지·점프 정밀도).**
