# [DAY5] 둔한 발 — 프레임 스킵 줄이기

> **DAY4까지의 결론**: 인식(구덩이 거리)·보상(통과 보너스) 둘 다 구덩이를 못 뚫었다.
> 남은 병목은 **제어 — 점프 정밀도**로 좁혀졌다. (상세: [\[DAY4\] 발밑의 함정](<[DAY4] 발밑의 함정 - 구덩이 거리 인식.md>))
> 이 문서는 제어를 직접 손본다 — 점프 한 번이 너무 듬성듬성(4프레임 한 덩어리)이라 타이밍을 못 맞추는 게 아닐까?
> 가설은 실험 *전에* 먼저 쓴다(예측→검증).

## 공통 설정 (트라이 간 고정)

DAY4와 동일, **트라이마다 딱 한 가지만** 바꾼다.

| 항목 | 값 |

## 트라이 1 — 프레임 스킵 4 → 2

### 변경
- `FRAME_SKIP` 4 → 2 (`mario_env_server.py`, Java 무관).
- 행동 1개를 2프레임만 유지 → 점프 궤적을 더 잘게 제어. 대신 소켓 왕복 2배 → 한 판이 ~2배 느려짐.

### 가설
- 구덩이를 못 넘는 게 "코앞인 걸 알면서도 점프 타이밍을 못 맞춰서"라면, 제어 해상도를 높이면 통과율↑·낙사↓ 나올까?
- 부작용: 스텝이 잘아져 같은 500판으로 도달 거리가 줄 수도(같은 ε 감쇠에 학습량은 그대로인데 한 스텝의 전진폭↓).
- 효과 있으면 → 병목이 제어가 맞다(해상도가 핵심). 없으면 → 해상도가 아니라 상태(공중 인지) 문제 = 다음은 yZone.

### 결과 — 구덩이 통과율은 약간 올랐지만 결정적이진 않다

![DAY5 트라이1 학습 그래프](images/day5-try1-graph.png)

비교 기준은 같은 보상(밟기·통과 +50)에서 FRAME_SKIP만 4였던 **DAY4 트라이2**.

| 지표 | DAY4 트라이2 (FS4) | **DAY5 트라이1 (FS2)** | |
|---|---|---|---|
| 평균 Max X | 737 | **741** | ≈ |
| 후반 100판 평균 Max X | — | 714 | |
| 낙사(dead_pit) | 120 | **100** | ▼ |
| 첫 구덩이 통과(>1145) | 46판(9%) | **56판(11%)** | 소폭▲ |
| **도달판 중 통과율** | 35% | **48%** | ▲ |
| best Max X | 1493 | **2466** | ▲(단일 분산) |

- **제어 해상도를 올리니 구덩이를 약간 더 넘는다**: 도달판 중 통과율 35→48%, 낙사 120→100. 가설 방향(제어가 병목)과 부합하는 양의 신호.
- **그런데 평균 Max X는 그대로**(737→741). 스텝이 잘아져 한 번에 덜 전진 → 통과율 이득을 도달거리 손해가 상쇄(예측한 부작용).
- **후반 greedy로 가도 안 오른다**: 100판 통과 `4→14→16→12→10`로 중반 정점 후 오히려 ↓, MA선(빨강)도 ε↓에 평평. DAY4와 똑같이 *추세 없이 진동.*

### 결론
- **가설 부분 적중: 해상도를 높이면 효과가 *조금* 있다**(도달판 통과율 35→48%·낙사 ▼). 병목이 제어라는 방향은 맞았다.
- 단 **FRAME_SKIP만으론 벽을 못 뚫는다** — 평균 거리 무변화·후반 추세 없음. 점프를 잘게 쪼개 줘도, AI는 *언제 뛸지*를 모른다(공중에 있는지조차 상태로 모름 — yZone이 지상·정점 모두 0).
- → 다음 트라이: **yZone을 살려 "공중 상태"를 상태에 넣는다**(상승/정점/하강 구분). 해상도(이번)에 더해 *공중 인지*를 주면 점프 타이밍을 배울 수 있는지 본다.

> 그래프: 파란점=굼바사망 · 주황점=구덩이낙사 · 회색=timeout/epsilon(우축) · 빨간선=Max X 20판 이동평균. 기준선: first Goomba(290)·2nd Goomba(722)·first pit(1120)·flag(3000).

## 트라이 2 — yZone 살리기 (공중 상태 인지)

### 변경
- **yZone 2단계 → 3단계**: 지상(`y<100`) / 낮은 공중(`100~150`) / 높은 공중·정점(`≥150`). 상태 720→1080(`StateEncoder`, `STATE_SIZE`도 갱신).
- 임계는 측정으로 확정: 종료 로그에 `minY`·`maxY`(y_pos 범위) 추가 → 실측 지상 79·점프 정점 160~199 기준으로 잡음. + 실패 원인(공중 인지 부족인지) 진단용.

### 가설
- 트라이1 결론이 "AI가 *언제 뛸지* 모른다 — 공중인지조차 모름"이었다. 공중 상태를 상태에 넣으면 점프 타이밍을 배워 구덩이 통과율↑·낙사↓ 나올까?
- **실패해도 분기점**: 공중을 알려줘도 안 넘으면 → "공중인 줄 몰라서"가 아니라 **상승/하강 타이밍(②)** 문제 → 다음은 속도 인식.

### 결과 — 신호는 살았지만 통과율은 안 올랐다

![DAY5 트라이2 학습 그래프](images/day5-try2-graph.png)

| 지표 | 트라이1 (yZone 2단계) | **트라이2 (yZone 3단계)** | |
|---|---|---|---|
| 평균 Max X | 741 | **701** | ▼ |
| 후반 100판 평균 | 714 | 665 | ▼ |
| 낙사(dead_pit) | 100 | **73** | ▼ |
| 첫 굼바 통과 | 70% | 64% | ▼ |
| 첫 구덩이 도달 | 117(23%) | 98(20%) | ▼ |
| 첫 구덩이 통과(>1145) | 56(11%) | 53(11%) | ≈ |
| **도달판 중 통과율** | 48% | **54%** | ▲ 소폭 |
| best Max X | 2466 | 1926 | ▼ |

- **신호는 진짜 살았다**: 모든 판이 점프(maxY≥100 500/500), yZone이 0→1→2로 변함. 트라이1의 "죽은 yZone"과 다름.
- **그런데 거의 다 약간 ▼.** 도달중 통과율만 48→54%로 소폭↑이나, 첫 구덩이 *도달 자체*가 23→20%로 줄어 통과 절대수는 비슷(56→53). 상태가 720→1080(+50%)으로 커져 같은 500판으론 학습이 더 희박해진 정황.
- **후반 greedy로도 안 오른다**: 100판 통과 `6→6→14→14→13`, MA선도 ε↓에 평평~하락.

### 결론
- **가설 기각 + 분기 확정.** 공중 상태를 정확히 알려줘도(yZone 작동 검증됨) **통과율은 안 올랐다.** 즉 못 넘는 이유는 "공중인 줄 몰라서(①)"가 **아니다.**
- **단 전반 ▼는 yZone이 해롭다기보다 부작용 정황**: 상태 720→1080(+50%)인데 학습은 500판 그대로라 희박해짐 + 단일 실행 분산. 낙사↓(100→73)·도달중 통과율↑(48→54%)이 "독은 아님"의 반증.
- 점프는 모든 판이 하고 공중인 것도 아는데 못 넘는다 → 남은 건 **②: 올라가는 중인지 내려오는 중인지(상승/하강 타이밍).** 위치(높이) 스냅샷 하나로는 같은 높이를 두 번 지나 ②를 못 푼다.
- → **다음 = 수직 속도 인식**(상승/정점/하강). #1·#2(위치/상태)는 ②를 못 푸니 건너뛰고, 속도(방향)를 상태에 넣는다. 상태 예산을 위해 yZone은 공중여부 2단계로 되돌리는 것을 검토.

> 그래프: 색·기준선은 트라이1과 동일.

## 트라이 3 — 수직 방향 인식 (높이 → 방향 교체)

### 변경
- **yZone(높이 3단계) → vy_dir(방향 3단계)로 교체**: 지상·정지(0) / 상승(1) / 하강(2). 상태 1080 그대로(높이를 버리고 방향을 얻음 — 트라이2가 "높이는 도움 안 됨"이었으므로).
- 방향은 **RAM 주소 추측 없이** Python에서 `Δy = 현재y − 직전y`로 계산(y_pos 위로 갈수록 큼 → Δy>0 상승). 임시 `[vy]` 로그로 점프 시 1↔2 전환 검증 후 제거.

### 가설
- 트라이2에서 "공중인 건 아는데 못 넘음 = ②(상승/하강 모호)"로 좁혔다. 방향을 직접 주면 **같은 높이의 상승/하강이 갈려** 구덩이 통과율↑?
- 효과 있으면 → ②가 병목 확정. 없으면 → 상태 정보로는 구덩이를 못 푼다(더 근본적 한계).

### 결과 — 신호는 진짜, 하지만 통과율은 또 안 올랐다

![DAY5 트라이3 학습 그래프](images/day5-try3-graph.png)

**① 방향 신호는 진짜다.** `[vy]` 검증: `79→84→93→108`(상승 dir=1) → `108→99→89→79`(하강 dir=2)로 정점에서 정확히 1↔2 전환. 모호함이 깨끗이 갈림.

**② 그런데 구덩이 통과율은 안 올랐다.**

| 지표 | 트라이2 (높이) | **트라이3 (방향)** | |
|---|---|---|---|
| 평균 Max X | 701 | **730** | ▲ 소폭 |
| 후반 100판 평균 | 665 | 717 | ▲ |
| 낙사(dead_pit) | 73 | 113 | ▲(도달 늘어 빠짐도 늚) |
| 첫 굼바 통과 | 64% | 68% | ▲ |
| 첫 구덩이 도달 | 98(20%) | 121(24%) | ▲ |
| 첫 구덩이 통과(>1145) | 53(11%) | 54(11%) | ≈ |
| **도달판 중 통과율** | 54% | **45%** | ▼ |
| best Max X | 1926 | 1671 | ▼ |

- 방향이 **전진·굼바엔 약간 도움**(평균 730·굼바 68%, 트라이 중 최고). 굼바를 더 넘어 구덩이까지 **더 도달**(24%).
- **하지만 구덩이 자체는 못 넘는다**: 도달중 통과율 45%로 오히려 ▼. 더 자주 도달해 더 자주 빠짐(낙사 113).
- **세 트라이 도달중 통과율: 48%(해상도) · 54%(높이) · 45%(방향)** — 다 ~50%에서 진동, 무엇을 줘도 못 넘는다.

### 결론
- **가설 기각.** 상승/하강을 정확히 갈라 줘도(②) 구덩이 통과율은 안 올랐다. ②도 결정적 병목이 아니었다.
- **DAY5 종합: 제어 상태 3종(해상도·높이·방향) 모두 구덩이 ~50% 벽을 못 넘었다.** "보상·인식으로 제어 못 풂"(DAY3·4)이 *제어 상태 정보*에도 그대로 적용됨 — 무엇을 알려줘도 도달중 절반은 빠진다.
- 남은 병목은 상태가 아니라 더 아래: **테이블 Q-Learning + 6개 이산 행동 + FRAME_SKIP 점프 물리의 표현력 한계**(또는 500판·1080상태 학습 예산). 다음은 상태 추가가 아니라 *알고리즘/행동/예산* 쪽을 봐야 한다.
- (단 셋 다 단일 실행이라 45~54% 차이는 분산일 수 있음. 견고한 건 "어느 것도 뚜렷이 못 올림".)

> 그래프: 색·기준선은 트라이1과 동일.
