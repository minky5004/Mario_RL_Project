## 트라이 1 — 프레임 스킵 4 → 2

### 변경
- `FRAME_SKIP` 4 → 2 (`mario_env_server.py`, Java 무관).
- 행동 1개를 2프레임만 유지 → 점프 궤적을 더 잘게 제어. 대신 소켓 왕복 2배 → 한 판이 ~2배 느려짐.

### 가설
- 구덩이를 못 넘는 게 "코앞인 걸 알면서도 점프 타이밍을 못 맞춰서"라면, 제어 해상도를 높이면 통과율↑·낙사↓ 나올까?
- 부작용: 스텝이 잘아져 같은 500판으로 도달 거리가 줄 수도(같은 ε 감쇠에 학습량은 그대로인데 한 스텝의 전진폭↓).
- 효과 있으면 → 병목이 제어가 맞다(해상도가 핵심). 없으면 → 해상도가 아니라 상태(공중 인지) 문제 = 다음은 yZone.

### 결과 — 구덩이 통과율은 약간 올랐지만 결정적이진 않다

![DAY5 트라이1 학습 그래프](images/day5-try1-graph.png)

비교 기준은 같은 보상(밟기·통과 +50)에서 FRAME_SKIP만 4였던 **DAY4 트라이2**.

| 지표 | DAY4 트라이2 (FS4) | **DAY5 트라이1 (FS2)** | |
|---|---|---|---|
| 평균 Max X | 737 | **741** | ≈ |
| 후반 100판 평균 Max X | — | 714 | |
| 낙사(dead_pit) | 120 | **100** | ▼ |
| 첫 구덩이 통과(>1145) | 46판(9%) | **56판(11%)** | 소폭▲ |
| **도달판 중 통과율** | 35% | **48%** | ▲ |
| best Max X | 1493 | **2466** | ▲(단일 분산) |

- **제어 해상도를 올리니 구덩이를 약간 더 넘는다**: 도달판 중 통과율 35→48%, 낙사 120→100. 가설 방향(제어가 병목)과 부합하는 양의 신호.
- **그런데 평균 Max X는 그대로**(737→741). 스텝이 잘아져 한 번에 덜 전진 → 통과율 이득을 도달거리 손해가 상쇄(예측한 부작용).
- **후반 greedy로 가도 안 오른다**: 100판 통과 `4→14→16→12→10`로 중반 정점 후 오히려 ↓, MA선(빨강)도 ε↓에 평평. DAY4와 똑같이 *추세 없이 진동.*

### 결론
- **가설 부분 적중: 해상도를 높이면 효과가 *조금* 있다**(도달판 통과율 35→48%·낙사 ▼). 병목이 제어라는 방향은 맞았다.
- 단 **FRAME_SKIP만으론 벽을 못 뚫는다** — 평균 거리 무변화·후반 추세 없음. 점프를 잘게 쪼개 줘도, AI는 *언제 뛸지*를 모른다(공중에 있는지조차 상태로 모름 — yZone이 지상·정점 모두 0).
- → 다음 트라이: **yZone을 살려 "공중 상태"를 상태에 넣는다**(상승/정점/하강 구분). 해상도(이번)에 더해 *공중 인지*를 주면 점프 타이밍을 배울 수 있는지 본다.

> 그래프: 파란점=굼바사망 · 주황점=구덩이낙사 · 회색=timeout/epsilon(우축) · 빨간선=Max X 20판 이동평균. 기준선: first Goomba(290)·2nd Goomba(722)·first pit(1120)·flag(3000).
